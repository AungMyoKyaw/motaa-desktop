## Conflict resolution and inheritance

1. Current implemented Native Precision v2 remains the production design source until a separately authorized v3 execution passes all promotion gates. Blue/Slate v2 is historical evidence and remains true of the *current master*. The new v3 approval supersedes its *future shell color direction* only.
2. Previous v2 action blue #1D61D6, brand blue #3378F6, cool surfaces, blue selection and blue focus must be migrated to v3 semantic bronze/gold values when execution is separately authorized; do not blanket-recolor source blue values inside astrology charts or the chart-theme Blue mode.
3. Retain v2 macOS layout, five workspaces, page associations, light-first policy, type scales, 4px grid, icon source, 1.75px Lucide stroke, working component assets and focus/keyboard/accessibility requirements.
4. Existing 44 native variables and 23 styles are the baseline, NOT an immutable ceiling. An execution may add/change UI semantic tokens while preserving native bindings and independent chart modes; all count deltas must be traced and audited.
5. Retain 90 app-state pages, 10 learning references, all original and included feature entries, traditional glyphs, four data-chart display modes, 2,160 navigation + 35 selection actions, and source-backed calculations without fake values.
6. Root DESIGN.md records the original cream/gold concept; design/README.md, design/tokens.css, AGENTS.md and v2 reviews accurately describe the currently implemented Blue/Slate shell. Do not rewrite their implemented-state assertions during planning. Update relevant current-state docs only as part of a separately authorized design execution and checked exports.
7. Chart states, all available for every user, must not be confused with subscription or licensing screens. iZarTarPro advertised-only calculations remain research-gated. No functional runtime is implied by FigCraft previews.
8. G32 and G34 are compatible: 90 pages are the final *scope*, while six pilot frames and an empty/error case are the mandatory intermediate review gate. G41 overrides any interpretation of G32/G37 as authorization now.

## Explicit exclusions

No dark appearance, chart recoloring, new routes, paid feature gates, screen deletions, font redistribution, runtime implementation, app refactor, git commit/push, publication or deployment. No further questions are needed to produce the design; new technical conflicts uncovered during future execution must be logged rather than silently changed.
